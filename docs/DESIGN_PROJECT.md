# ExamTraining — дизайн-проект и спецификация

Версия документа: **7.0 — multi-subject + tickets**

## 1. Назначение

Офлайн-тренажёр для подготовки по нескольким учебным предметам. Один APK может содержать любое количество предметов, при этом интерфейс, режимы обучения и тестирования общие.

Текущий комплект данных содержит предмет **«Фармакология»** с 369 вопросами, но архитектура не привязана к этому числу и не привязана к фармакологии.

## 2. Основной принцип многопредметности

На основных экранах вместо фиксированного названия приложения показывается **название текущего предмета**.

Пример:

```text
Фармакология  ⌄
369 вопросов
```

Нажатие на название открывает список предметов:

```text
Предмет

✓ Фармакология     369 вопросов
  Анатомия         500 вопросов
  Биология         240 вопросов
```

После выбора предмета:

- интерфейс остаётся на том же наборе вкладок;
- загружается банк выбранного предмета;
- используется отдельный прогресс выбранного предмета;
- тесты формируются только из вопросов выбранного предмета.

## 3. Хранение данных

Источник истины:

```text
data/subjects/
├── pharmacology.json
├── anatomy.json
├── biology.json
└── _subject_template.json
```

**Один JSON = один предмет.**

Файлы, начинающиеся с `_`, не попадают в приложение.

Метаданные предмета:

```json
{
  "subject": {
    "id": "anatomy",
    "title": "Анатомия",
    "language": "ru",
    "order": 20
  }
}
```

`subject.id` — постоянный технический идентификатор и ключ прогресса.  
`subject.title` — видимое название.  
`subject.order` — порядок в меню выбора.

Количество заданий, билетов и автоматически проверяемых вопросов вычисляется автоматически.

Полная схема: `docs/SUBJECTS_DATA_FORMAT.md`.

## 4. Runtime-архитектура данных

Канонические JSON не подключаются к WebView напрямую.

Скрипт:

```text
tools/build_data_bundles.py
```

генерирует:

```text
app/src/main/assets/subjects_core.js
app/src/main/assets/subject_data/<id>_explanations.js
```

`subjects_core.js` содержит короткие рабочие данные всех предметов:

- метаданные;
- вопросы;
- варианты;
- ключи;
- соответствия;
- допустимые текстовые ответы;
- структуры билетов.

Подробные разборы и развёрнутые ответы на билеты находятся в отдельных файлах каждого предмета и загружаются лениво только при необходимости.

Это сохраняет один редактируемый JSON на предмет и не заставляет приложение разбирать все длинные объяснения при старте.

## 5. Поддерживаемые типы вопросов

- `single_choice` — один правильный вариант;
- `multiple_choice` — несколько правильных вариантов;
- `open_text` — текстовый ответ;
- `matching` — соответствие;
- `ticket` — билет с развёрнутым ответом.

Для одного ответа используются круглые radio-индикаторы.  
Для нескольких — квадратные checkbox-индикаторы.  
Для соответствий используется раскрывающийся список вариантов внутри каждой строки, без системных `<select>`.
Для билета варианты выбора отсутствуют: сначала показывается формулировка, затем кнопка «Показать ответ», после раскрытия — «Знаю» и «Повторить».

## 6. Навигация

Нижняя панель:

1. **Учить**
2. **Тест**
3. **Банк**
4. **Прогресс**

Настройки доступны через кнопку шестерёнки.

## 7. Экран «Учить»

Верх:

```text
Название предмета ⌄        ⚙
N заданий
```

Далее:

- выучено;
- ошибки;
- процент прогресса;
- «Продолжить»;
- «По порядку»;
- «Случайно»;
- «Только ошибки».

### По порядку

1. Сначала новые задания в порядке массива JSON.
2. Ошибка в тестовом вопросе или отметка «Повторить» у билета добавляет задание в конец очереди.
3. Пока остаются новые вопросы, ошибка не возвращается вперёд.
4. После новых вопросов идёт очередь ошибок.
5. Повторная ошибка снова перемещает вопрос в конец.
6. Правильный ответ удаляет вопрос из очереди ошибок.

## 8. Экран вопроса

Верхняя панель:

```text
← | По порядку ▾ | №127 / 369
```

Затем:

1. тип задания;
2. формулировка;
3. элементы ответа;
4. результат;
5. сворачиваемые разборы.

Нижняя фиксированная панель:

```text
[ Проверить ] [ Не знаю ]
```

после проверки:

```text
[ Следующий вопрос ] [ В банк ]
```

## 9. Тест

Количество тестовых вопросов зависит от размера текущего предмета. Показываются варианты 20 / 50 / 100 только если они меньше числа автоматически проверяемых вопросов, плюс **«Все»**. Билеты в тест не входят.

Настройка:

- показывать ответ сразу: Да / Нет.

После теста:

- donut-диаграмма;
- правильно / неправильно;
- сначала все ошибки;
- затем правильные;
- ответ пользователя;
- правильный ответ;
- сворачиваемые разборы.

## 10. Банк

Банк всегда относится к текущему предмету.

- поиск по формулировке задания и вариантам;
- тип задания виден в списке, включая «Билет»;
- статус: не отвечен / повторить / закрыт;
- переход к заданию.

## 11. Прогресс

Прогресс независим для каждого предмета.

Хранятся:

- records;
- errorQueue;
- lastMode;
- lastQuestionId;
- testFeedback.

Ключ localStorage:

```text
exam_subject_state_v1::<subject.id>
```

Прогресс хранится в пространстве ключей `examtraining_*` отдельно для каждого `subject.id`.

Сброс прогресса на экране прогресса очищает **только текущий предмет**.

## 12. Тема

Тема глобальна для приложения, а не для отдельного предмета.

Режимы:

- Системная;
- Светлая;
- Тёмная.

Отдельно настраиваются палитры светлой и тёмной темы:

- акцент;
- фон;
- поверхность;
- текст;
- границы;
- правильный ответ;
- ошибка.

## 13. Визуальная система

Используется 4 px grid.

Основные интервалы:

- 4 px — тесно связанные элементы;
- 8 px — малый отступ;
- 12 px — компактный внутренний;
- 16 px — основной;
- 24 px — крупный блоковый;
- 32 px — разделение крупных секций.

Основной radius — **4 px**.

Интерфейс прямоугольный, без декоративных больших скруглений.

## 14. Android

- WebView работает только с локальными assets;
- сетевые загрузки заблокированы;
- разрешения не запрашиваются;
- `minSdk 23`;
- `targetSdk 35`;
- `compileSdk 35`;
- Java 17.

## 15. Добавление предмета без изменения кода

Для нового предмета не требуется менять Java, HTML, CSS или `app.js`.

Нужно:

1. добавить `data/subjects/<subject>.json`;
2. выполнить `python tools/build_data_bundles.py`;
3. пересобрать APK.

Это является штатным способом расширения приложения.


## Безопасный выбор цвета

Настройка пользовательских цветов не использует HTML `input type="color"`. Нажатие на цветной образец открывает встроенный редактор RGB + HEX внутри WebView. Это исключает зависимость от системного Android color chooser и предотвращает падение на несовместимых версиях WebView.
